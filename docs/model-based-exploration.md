## 1. 问题定位

源笔记将研究对象定义为：月面未知环境中，轮式无人平台需要在多类环境与平台约束共同作用下，自主选择探索目标，并规划局部与全局路径。

与“基于模型的自主探索算法”直接相关的核心约束包括：

- 坡度
- 障碍
- 崎岖度
- 光照
- 平台能力
- 任务价值
- 地图可信度

因此，该算法不应只做单纯的未知区域搜索，也不应只做路径最短规划，而应围绕“环境-平台-约束模型”建立可更新的世界表达，并在该模型上完成目标选择、路径规划、执行反馈和重规划。

## 2. 总体闭环

源笔记明确给出的研究逻辑是：

```text
建模认知 -> 探索决策 -> 路径执行 -> 观测反馈
```

对应到算法系统，可拆为四个层次：

| 层次 | 作用 | 对应开发模块 |
|---|---|---|
| 建模认知 | 表达世界状态、平台能力、地图可靠性 | 多层动态地图、可信度地图、综合代价地图 |
| 探索决策 | 判断下一步探索哪里 | 探索目标候选生成、目标效用函数、目标排序 |
| 路径执行 | 判断目标是否可达，并生成可执行路径 | A* 全局规划、局部安全走廊、轨迹优化 |
| 观测反馈 | 用执行后的观测更新地图与可信度 | 观测更新、代价更新、重规划触发 |

这一闭环意味着：目标选择不能脱离路径规划，路径规划也不能脱离地图可信度与观测反馈。

## 3. 模型层：环境-平台-约束与可信度

模型层是自主探索算法的底座，负责回答三个问题：

1. 当前世界状态如何表达。
2. 平台能力如何约束可通行区域。
3. 地图信息是否可靠。

源笔记推荐从“最小可用的多层动态地图与可信度地图”开始。面向开发实现，可以先抽象为网格地图，每个栅格维护若干层信息：

| 地图层 | 含义 | 用途 |
|---|---|---|
| 地形坡度层 | 表示区域坡度风险 | 影响通行代价与可通行性 |
| 障碍层 | 表示岩石、坑洞等障碍 | 判定不可通行或高风险区域 |
| 崎岖度层 | 表示地形粗糙程度 | 影响平台通过风险和能耗 |
| 光照层 | 表示局部光照条件 | 影响感知质量、能源或任务价值 |
| 平台能力层 | 表示平台运动与越障能力约束 | 将环境约束转化为平台可执行约束 |
| 任务价值层 | 表示探索区域收益 | 支撑探索目标效用计算 |
| 可信度层 | 表示地图或观测可靠程度 | 支撑未知区域选择和重规划 |
| 综合代价层 | 融合风险、约束与任务因素 | 供全局/局部路径规划使用 |

模型层的关键输出不是单一地图，而是供决策和规划共同使用的“可达性、风险、收益、可信度”组合表达。

## 4. 决策层：自主探索目标选择

源笔记指出，自主探索目标选择是决策层，依赖模型与可信度来判断下一步探索哪里，并需要路径规划反馈目标是否可达、代价是否合理。

因此，探索目标选择至少需要包含三类输入：

- 地图输入：未知区域、低可信度区域、任务价值区域。
- 约束输入：坡度、障碍、崎岖度、光照、平台能力。
- 规划反馈：候选目标的可达性、路径代价、风险代价。

目标效用函数应同时考虑收益和代价。源笔记未给出具体公式，开发初期可以保留为可替换接口：

```text
utility(target) = information_gain + mission_value - travel_cost - risk_cost
```

其中各项含义建议如下：

| 项 | 含义 |
|---|---|
| `information_gain` | 探索该目标后可能提升的地图认知或可信度 |
| `mission_value` | 目标区域本身的任务收益 |
| `travel_cost` | 从当前位置到目标的路径代价 |
| `risk_cost` | 路径或目标区域的地形、障碍、光照等风险 |

该公式只是开发占位形式，后续需要根据实验目标、地图表达和平台模型确定权重与归一化方式。

## 5. 规划层：全局与局部路径规划

源笔记将全局与局部路径规划定义为执行层，其输入包括探索目标和综合代价地图，输出是可执行路径。执行后观测再反向更新地图与可信度。

推荐实现顺序为：

1. 建立 A* 全局规划基线。
2. 基于综合代价地图生成可行路径。
3. 将规划结果反馈给目标选择模块，过滤不可达或代价过高的目标。
4. 扩展局部安全走廊、IRIS/GCS 或轨迹优化。

开发初期，全局规划可以先承担两个职责：

- 为当前最优目标生成路径。
- 为候选目标提供代价评估，参与目标效用排序。

局部规划或轨迹优化可以作为后续增强模块，不应阻塞最小闭环的实现。

## 6. 观测更新与重规划

源笔记强调“执行后的观测再反过来更新地图与可信度”。这意味着算法需要支持动态循环，而不是一次性规划。

最小闭环可设计为：

```text
读取当前地图与平台状态
生成候选探索目标
调用全局规划评估候选目标
选择效用最高且可达的目标
规划并执行一段路径
接收新观测
更新多层地图与可信度地图
判断是否需要重规划
```

重规划触发条件可以先从以下情况开始：

- 当前目标变为不可达。
- 路径上出现新障碍或高风险区域。
- 新观测显著改变目标区域可信度。
- 候选目标效用排序发生明显变化。

## 7. 最小可用版本建议

结合源笔记推荐路线，`model-explorer` 的首个可用版本可按以下顺序实现：

1. 多层网格地图与可信度地图。
2. 综合代价地图生成。
3. A* 全局路径规划基线。
4. 候选探索目标生成。
5. 探索目标效用函数。
6. 观测更新与地图可信度更新。
7. 目标选择、路径规划、观测反馈、重规划闭环。

首版应重点验证闭环是否成立，而不是立即引入复杂局部规划或轨迹优化。

## 8. 建议的代码模块边界

面向后续实现，可初步划分为：

| 模块 | 职责 |
|---|---|
| `map_model` | 管理多层地图、可信度地图和综合代价地图 |
| `exploration` | 生成候选目标并计算目标效用 |
| `planning` | 提供 A* 全局规划和路径代价评估 |
| `observation` | 将新观测写回地图并更新可信度 |
| `loop` | 串联建模、决策、规划、反馈和重规划 |
| `simulation` | 提供月面环境、平台状态和传感器观测的测试场景 |

这些模块边界来自源笔记中的闭环逻辑，具体命名和接口可在代码实现时再根据语言与框架调整。

## 9. 待明确问题

源笔记目前给出了研究逻辑和技术路线，但以下内容仍需后续补充：

- 多层地图的数据结构采用栅格、点云、拓扑图还是混合表达。
- 坡度、障碍、崎岖度、光照等约束如何量化。
- 平台能力模型需要包含哪些运动学或动力学约束。
- 地图可信度如何更新，是否区分观测可信度和预测可信度。
- 探索目标效用函数的权重如何设置。
- A* 综合代价地图中各类风险项如何归一化。
- 局部安全走廊、IRIS/GCS 和轨迹优化分别在何种阶段引入。

这些问题不影响最小闭环启动，但会决定后续算法效果和实验可信度。
